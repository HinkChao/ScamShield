# Contributing to ScamShield AI

Thank you for contributing to ScamShield AI!

This project is developed collaboratively as part of the Fall 2026 Collaborative Hackathon.

## 1. Team Collaboration Principles

ScamShield AI operates without a designated team leader.

All team members have equal opportunities to propose ideas, discuss technical decisions, review contributions, and participate in project planning.

Responsibilities are distributed according to interests, expertise, availability, and team agreement.

**Repository ownership does not determine project leadership.**

Equal participation does not require everyone to perform identical tasks. Each contributor is responsible for communicating progress and completing agreed deliverables.

## 2. Team Roles

The following workstreams are proposed:

1. Product, Research & Integration
2. Machine Learning & AI Engineering
3. Cybersecurity & URL Engineering
4. Application & UI Development
5. Evaluation, Testing & Quality Assurance
6. UX, Outreach & Responsible AI

These are functional responsibilities, not hierarchical positions.

Members may contribute across multiple areas. Final assignments will be agreed upon after the team's Discord role-selection discussion.

## 3. GitHub Development Workflow

To keep the shared project organized:

1. Start from the latest `main` branch.
2. Create a separate branch for a specific task.
3. Make and test your changes.
4. Commit changes using a descriptive message.
5. Open a pull request targeting `main`.
6. Invite teammates to review the changes.
7. Discuss and address feedback.
8. Merge after the agreed review process.

Avoid committing unfinished or unreviewed features directly to `main`.

### Suggested Branch Names

- `docs/project-documentation`
- `feature/phishing-classifier`
- `feature/url-analysis`
- `feature/streamlit-ui`
- `feature/explanation-engine`
- `test/model-evaluation`
- `fix/input-validation`

## 4. Commit Message Guidelines

Use short, descriptive messages.

Examples:

- `docs: update project README`
- `feat: implement URL extraction`
- `feat: add phishing classification`
- `test: add URL analyzer tests`
- `fix: handle empty user input`
- `refactor: simplify risk engine`

## 5. Pull Request Guidelines

A pull request should explain:

- What was changed.
- Why the change is necessary.
- How it was tested.
- Any limitations or known issues.
- Whether the change affects other components.

At least one teammate should review substantial changes when practical.

Pull requests should remain open for discussion until the team agrees they are ready to merge.

## 6. Technical and Security Standards

All contributors should:

- Avoid committing passwords, API keys, or secrets.
- Treat submitted messages and URLs as untrusted input.
- Never automatically open potentially malicious links.
- Avoid collecting unnecessary personal information.
- Document external datasets, models, and libraries.
- Include tests for new or modified functionality.
- Report known limitations and uncertainty.
- Avoid claiming unverified AI detection accuracy.

## 7. Communication and Decision-Making

Discord is used for team discussions and coordination.

GitHub Issues and pull requests should document technical tasks, changes, and reviews.

Significant decisions about project scope, architecture, and responsibilities should be discussed collaboratively.

When disagreements arise, contributors should compare evidence, implementation feasibility, security implications, and hackathon requirements before reaching a decision.

## 8. Recognition and Contributions

Contributions should be recognized based on actual work, including research, coding, testing, design, documentation, and presentations.

The team will maintain a contribution record reflecting each member's work.

All contributors should receive appropriate acknowledgment.

## 9. Project Priorities

During the hackathon, prioritize:

1. A functioning end-to-end prototype.
2. Explainable, evidence-grounded phishing analysis.
3. Safe processing of messages and URLs.
4. Reproducible testing and honest evaluation.
5. Accessible multilingual explanations.
6. A reliable final demonstration.

Optional features should not delay the core working prototype.

---

**ScamShield AI is a shared project built through collaboration, technical responsibility, and mutual respect.**
